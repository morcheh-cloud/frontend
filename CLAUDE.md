## Commands

```bash
pnpm dev                           # dev server on :3200 (`pnpm start` serves prod on :3200 too)
pnpm build                         # production build — run before declaring work done (stops a running `pnpm dev`: restart it after)
pnpm lint                          # Biome check (lint + format + import order) — must pass (RTK mangles its output: use `rtk proxy pnpm lint`)
pnpm lint:fix                      # apply Biome's safe fixes + formatting
pnpm gen:api                       # regenerate src/lib/services.ts from the backend spec (backend must be up; override with OPENAPI_URL)
pnpm dlx shadcn@latest add <name>  # add a shadcn component
```

Docker: `Dockerfile` (Node 26 slim, pnpm via npm since Node 25+ has no corepack, `output: "standalone"` in `next.config.ts`, runs `node server.js` on :3200 as `node`); `NEXT_PUBLIC_API_URL` is a required build arg (baked in). Full stack: `../backend/deploy/compose.yml`.

## Product & app state

- Morche ("ant"): SSH-based server management + monitoring for small/medium orgs — servers and the services on them in one place. Display name is "Morche" (renamed 2026-11-11); lowercase `morcheh` identifiers (localStorage keys, `urn:morcheh:*`, cookie, server paths, log format) stay as they are, and `src/lib/services.ts` keeps the backend's spelling until the backend is renamed.
- Local setup: `cp .env.example .env.local` (else requests go to :3200 and 404).
- Backend lives in `../backend` (Go, see its CLAUDE.md); dev server on `:8080`, Swagger UI at `/docs`, OpenAPI spec at `/openapi.json` (use it to type/generate API calls).
- Dev services (user rule): anything needed for development (MinIO on :9100, later databases…) runs as a container in `../backend/docker-compose.yml`, started with `make up` there; no plain `docker run`.
- Auth & access (guide `access`): session cookie set by the backend (`credentials: "include"`), nothing stored in JS. `AuthGate` (`src/components/auth/auth.tsx`, wraps the panel and `/help`) decides by `/auth/me`: signed out → `/login?next=`, `must_change_password` → `MustChangeView`, `pending` → `WaitingView` (polls, opens by itself), else the app; any 401/403 re-checks `/auth/me` (`onRefused` in `api.ts`) and a lost session goes to login; `clearLocalData()` runs on sign out and when another user signs in on the same browser. Locked out of every admin = backend `server reset-admin` (guide `access#locked-out`). `/login` shows `signup-form` for first-run setup (`kind="setup"`, setup token if the backend needs it) or public registration. `useAuth()` = user + `signOut`; `useAccess()` = `admin`, `serverLevel(id, workspaceId)`, `storageLevel`, `appLevel`, `workspaceLevel`, `canCreateIn`. Levels in `auth/level.ts` (`atLeast`, labels, hints). **The backend enforces everything; the UI only hides what it would refuse:** `useServerCan()` / `useWorkspaceCan()` (`servers/components/permissions.ts`), the storage one in `storage/components/permissions.ts`, `sectionMin`/`sectionsFor` in `sections.ts` for server tabs (a too-low direct URL shows "You need X access"), `FileSource.listOnly` for a Viewer's storage. ## Conventions (from the user)

- It's an admin panel: **no SSR data and no Server Actions.** Every request runs client-side; pages that fetch are client components.
- Requests go through **TanStack Query**: `useQuery` for reads, `useMutation` for writes. HTTP lives in `src/lib/api.ts` (base URL `NEXT_PUBLIC_API_URL`, see `.env.example`): use the generated typed client `api` (e.g. `api.system.getHealth()`, grouped by OpenAPI tag, resolves to the body) for endpoints in the spec; `apiFetch` only for endpoints not in the spec yet. Both throw `ApiError` (message = Huma problem `detail`). Huma rejects unknown body fields (422 "validation failed", `unexpected property`): never spread local helper keys (e.g. a `kind` discriminator) into a request body. `src/lib/services.ts` is generated by `script/genApi.ts` (swagger-typescript-api, fetch) — never edit it by hand; rerun `pnpm gen:api` after backend API changes. `QueryClientProvider` lives in `src/components/providers.tsx`, mounted in the root layout.
- Folder layout: components used by one page only → `src/app/<route>/components/`; that route's request functions → `src/app/<route>/api.ts`. Anything reused (or likely to be) → `src/components/`. Keep each page fairly self-contained (soft rule).
- Installing packages is fine wherever it's the best-practice choice.
- Secret fields: use `SecretInput` / `PrivateKeyInput` (`src/components/secret-input.tsx`), never a bare `type="password"`. Pass `load` when a value is saved: the eye shows it as the placeholder, so the field stays blank and "blank = keep" still holds.
- Shared overlays: `BottomSheet` / `SheetAction` (`src/components/bottom-sheet.tsx`, Base UI Drawer) for phones; `ResponsiveDialog` / `ConfirmDialog` (`src/components/responsive-dialog.tsx`) = centred dialog on desktop (never taller than the window: header/footer fixed, body `[data-slot=dialog-body]` scrolls; a form's own action row can be `sticky bottom-0`), bottom sheet on phones. Toasts: `sonner` (`toast()`), `<Toaster>` in `providers.tsx`. Form errors: `fieldErrors(err)` in `api.ts` maps Huma `errors[].location` to field names.
- URL state: `nuqs` (adapter in `providers.tsx`; servers filters use `history: "replace"`). Build links into another page's URL state with that page's `createSerializer` (`serversHref`, `terminalHref`), never by hand-concatenating `?key=`. **Gotcha:** `useOpen` pushes a history entry, so a URL write made while a sheet is open is undone by the Back that closes it. Close first, then write on `popstate` (see `afterClose` in `servers-mobile.tsx`). Exception: a file picker must open synchronously inside the tap, so pick first, then close.
- Reusable hooks live in `src/hooks/` (put new shared hooks there too):
  - `usePersistedQuery` — `useQuery` + long-term IndexedDB cache (localforage, default TTL 30 days) for data that rarely changes. Same options as `useQuery` plus `ttl`.
  - `useIsPhone()` — `boolean | null` (`max-width: 767px`, null until known); use it to pick separate desktop/mobile components.
  - `useBack(parent)` — phone Back button: `router.back()` if the previous route is `parent`, else `router.replace(parent)` (deep links). `useBackOr(fallback)` = `router.back()` if there is any in-app history, else `router.replace(fallback)`. Both need `<RouteHistory>` (mounted in the panel layout).
  - `useStoredChoice(key, values)` — a remembered choice (view mode…) in localStorage, validated against `values`; falls back to the first one.
  - `useOpen(id)` — `useState<boolean>`-shaped open state for modals/sheets/drawers; pushes a history entry so phone Back closes the layer instead of leaving the page. **Use it for every modal, sheet and drawer.**

## Mobile = native app (strict, from the user)

- On phones the panel must look and behave like a native mobile app, with all mobile-app best practices (full-screen views, no web-style cards floating on canvas, bottom sheets over centred dialogs, ≥44px touch targets, safe-area insets, sensible keyboard hints, Back closes layers via `useOpen`, no hover-only affordances).
- If one responsive component can't give the best UX on both, write **separate desktop and mobile components** instead of compromising.
- Already in place: `viewport` in root layout (`viewportFit: cover`, `interactiveWidget: resizes-content`, theme color per theme: `themeColors` in `src/lib/theme-script.ts`), no tap highlight / overscroll bounce in `globals.css`, inputs `h-11` (44px) below `md`. ## Stack notes

- `cacheComponents` is on. `usePathname()`/`useParams()` suspend on dynamic routes: read them under `<Suspense>` (shell pieces use `<WithPathname>` from `src/components/panel/with-pathname.tsx`) or dev logs an error. Pages that wait on client-loaded data export `instant = false` (from a server `page.tsx`; a layout's `false` doesn't cover its pages), else dev warns "Could not validate … instant navigation".
- `next.config.ts`: **React Compiler is on** (`reactCompiler` + Rust `turbopackRustReactCompiler`; code must follow the Rules of React, no new `useMemo`/`useCallback` needed), plus experimental `useOffline`, `turbopackGc`, FS cache, `optimizePackageImports` (@xyflow, @uiw/react-codemirror, @dnd-kit).
- shadcn style is `base-nova`: components are built on **Base UI** (`@base-ui/react`), not Radix. Check a component's props against Base UI before using Radix-style APIs (e.g. `asChild`).
- `cn` is exported from `@/lib/utils`: the `cn` package configured with our type scale (`text-caption`, `text-body-sm`…). Always import it from there, including in `src/components/ui/` — the bare `cn` package treats those sizes as colors and drops them next to `text-ash` etc.
- `components.json` has `"rtl": true`, so shadcn emits logical classes (`ms-*`, `ps-*`, `start-*`). Keep using logical classes in our own code too. The UI itself is **English, LTR** (`lang="en"`).
- Path alias: `@/*` → `src/*`.
- Security headers for every page are set in `next.config.ts` `headers()` (CSP `frame-ancestors 'none'`/`object-src`/`base-uri`/`form-action`, X-Frame-Options DENY, nosniff, `Referrer-Policy: same-origin`, COOP, Permissions-Policy, HSTS). No `script-src`/`connect-src` yet (Next inline scripts need a nonce); add a directive only after checking every page still works.
- TypeScript 7 (native `tsc`, no JS compiler API and no `tsserver.js`): `next build` type-checks with the project's `tsc` CLI (`experimental.useTypeScriptCli`, on by default — never set it `false`); check by hand with `rm -f tsconfig.tsbuildinfo && npx tsc --noEmit -p .` (a stale tsbuildinfo can hide errors). VS Code falls back to its bundled TypeScript, so the Next.js editor plugin doesn't run against the workspace version.
- Drag and drop: `@dnd-kit/core` + `@dnd-kit/sortable` (used by `/services`). Rows that drag on touch get `select-none [-webkit-touch-callout:none]` and drop the context menu; a drag must never be the only way to move something.
- `ItemMenu` with a custom `trigger` renders only that element: put the `<Ellipsis />` inside it yourself.
- Gotchas: an inline `ref={(el) => …}` reruns on every render (focus/select-on-mount refs must be stable: `useCallback` or a module function, else typing gets reselected). Unwrapped wide content (read-only CodeMirror, wide tables) widens the whole page through the flex parents' min-content even inside `overflow-auto`: give its card `[contain:inline-size]`. CodeMirror's `onStatistics` fires every render — store only real changes or it loops. A Base UI `Button` with `render={<a/>}` needs `nativeButton={false}`.
- Browser testing via chrome-devtools: under mobile emulation, `click` by uid is unreliable; use `evaluate_script` with `el.click()`. If its profile is locked by another Chrome, run your own headless Chrome (`--remote-debugging-port` on a free port — never drive another session's Chrome, scratch `--user-data-dir`) and drive it over CDP; Base UI menus need real `Input.dispatchMouseEvent` clicks, not `el.click()`. To test writes without touching real data: a scratch database + backend on :8081 and Chrome with `--host-resolver-rules="MAP localhost:8080 127.0.0.1:8081"`. Pages stay mounted hidden after leaving them (state survives Back, a hidden `[role=dialog]` has width 0), and a dirty page's `beforeunload` blocks CDP `Page.navigate` until the dialog is answered.
- Scrollbars are styled globally in `globals.css` (slim Mist thumb; `html { scrollbar-gutter: stable }` so menus/dialogs locking scroll or content starting to overflow never shift the page width). Hide a scrollbar with the `no-scrollbar` utility or `[scrollbar-width:none]`; don't set `scrollbar-color`/`scrollbar-width: thin` on elements (Chrome then drops the custom style).
- Lint/format is **Biome only** (`biome.json`); no ESLint or Prettier. Style: 2 spaces, double quotes, no semicolons, 80-column lines, Tailwind classes auto-sorted. Suppress with `// biome-ignore <rule>: <reason>`. `src/lib/services.ts` (generated) and `public/` are excluded; Markdown isn't formatted.

- No "island" layouts: the panel is a full-height sidebar + a plain body that scrolls with the document; no inset rounded box around page content. No alternating dark/light bands.
- One chromatic accent: indigo (`brand`). No other colored CTAs or controls; status colors only when a real status needs them.
- **The one exception (user-approved):** the `--color-svc-*` palette in `globals.css` (`appColors` in `src/components/palette.tsx`, stored as keys, never hex), used only behind a service's or a workspace's logo/letter and on a service category's dot.
- Icons: **only** `lucide-react` (lucide.dev), outlined, ~20px in feature cards. No other icon sets.
- No photography or illustrations. Imagery is product UI screenshots, partner logos, avatars.
- When adding a shadcn component, check its classes against these rules and adjust it in `src/components/ui/` if it drifts (e.g. wrong radius, heavy shadow, bold title).

For component recipes (nav bar, hero, feature cards, testimonial, stat block, footer), follow the **Components** section of DESIGN.md.
